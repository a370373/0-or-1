## 💡 專案介紹

**01** 是一個使用 Rust 開發的原生機器碼載入器。

它探索一個簡單的想法：

> 如果電腦最終執行的是機器碼，那麼能不能直接把機器碼寫成文字，再由自己的載入器解析並執行？

一般軟體開發會使用高階程式語言、組合語言或其他中間表示，再透過編譯器或組譯器產生機器碼。

`01` 則選擇直接使用二進位文字作為原始碼表示形式。載入器會將 `.01` 檔案中的 `0` 和 `1` 解析成位元組，配置可執行記憶體，再依照約定的入口介面呼叫原生機器碼。

```
       hello.01
           │
           ▼
    讀取二進位文字
           │
           ▼
       解析 0 和 1
           │
           ▼
   每 8 個有效位元組成 1 位元組
           │
           ▼
      原生機器碼位元組
           │
           ▼
      配置可執行記憶體
           │
           ▼
      呼叫原生機器碼
           │
           ▼
       CPU 執行指令 ⚙️
```

整個流程不需要先將 .01 轉換成 .bin、.elf、.exe 等中間檔案。

01 不是另一套 CPU 指令集，也不是指令集模擬器；它直接處理目標處理器原本就能理解的機器指令。

## 🤡 別人寫程式，再編譯成機器碼 我們直接把機器碼寫出來。

## 🧠 核心理念

1️⃣ 不重新發明程式語言

01 不打算創造一套新的高階程式語言，而是直接使用二進位文字表示機器碼。

2️⃣ 不創造新的指令集

CPU 已經有自己的指令集。01 不另外發明 ISA，而是使用目標 CPU 原本支援的指令。

3️⃣ 讓原始碼回到最基本的位元

.01 的有效內容只有兩種數字：

0
1

每 8 個有效位元組成一個位元組。這些位元組可以代表機器指令，也可以包含機器碼需要使用的資料。

4️⃣ 文字負責表示，載入器負責執行

.01 是文字格式，不是直接儲存的原生執行檔。載入器負責將文字解析成位元組，再透過平台相依的執行機制呼叫機器碼。

5️⃣ 保留人類閱讀的註解

雖然原始碼使用二進位表示，仍然可以加入 # 註解，記錄位元組用途、指令意義與程式邏輯。

二進位可以很難閱讀，但開發過程仍然可以有文件。 🤣

## ✨ 主要特色

🔢 二進位文字原始碼：使用 0 和 1 表達機器碼。

⚙️ 原生機器碼執行：呼叫原生機器碼，而不是模擬另一套指令集。

🦀 Rust 載入器：使用 Rust 實作解析與執行流程。

📄 .01 檔案格式：以純文字保存二進位表示。

🚫 不需要中間二進位檔：直接解析 .01，不必先輸出 .bin。

💬 支援 # 註解：註解不會轉換成機器碼。

🧹 忽略空白與換行：可以安排二進位文字的排版。

🧪 檔案格式檢查：可以在執行前驗證 .01 格式。

🧱 平台相關模組：將平台執行機制與主要流程分開。

🔁 子程序執行模式：透過子程序執行機器碼，隔離部分程序層級的失敗。

## 📄 .01 檔案格式

.01 是以二進位文字表示位元組的純文字格式。

🔢 基本規則

內容	意義

0	二進位位元 0
1	二進位位元 1
空格、Tab、換行	忽略
其他 ASCII 空白字元	忽略
#	開始註解，直到該行結束


除了註解與允許的空白之外，其他字元都會被解析器拒絕。

有效位元的數量必須是 8 的倍數，而且檔案必須至少包含一個完整位元組。

## 📝 範例

```
# 第一個位元組
01001000

# 第二個位元組
01101001

解析結果：

01001000 → 0x48
01101001 → 0x69

💬 行內註解

01001000 # H
01101001 # i
```
```
#
```
後面的內容會被忽略，不會被轉換成位元組。

## 🧹 空白排版

以下兩種寫法具有相同的有效位元：

01001000

0100 1000

空白只影響閱讀方式，不會改變解析結果。

## ❌ 不合法的內容

不完整的位元組：

0100100

非法字元：

0100100X

只有空白或註解、沒有任何有效位元組的檔案也會被拒絕。

## ⚙️ 執行原理

1️⃣ 讀取 .01

載入器讀取文字檔案，取得其中的二進位文字。

2️⃣ 解析位元

解析器忽略允許的空白與 # 註解，將每 8 個有效位元轉換成一個位元組。

3️⃣ 驗證格式

檢查非法字元、不完整的位元組，以及沒有有效位元組的檔案。

4️⃣ 配置可執行記憶體

載入器使用平台提供的機制，配置符合執行要求的記憶體。

5️⃣ 呼叫原生機器碼

目前的執行介面使用固定的 C ABI 入口：

int entry(int argc, const char *const argv[]);

因此，.01 中的機器碼必須符合這個入口介面的呼叫慣例。

6️⃣ 處理執行結果

機器碼完成執行後，載入器會依照目前的執行流程處理結果。

## ⚠️ 01 目前不是完整的原生執行檔載入器。它不會自動處理 ELF、PE 或 Mach-O 的完整載入流程，也不會自動完成所有重定位、動態連結或原生程式啟動程序。

## 🌍 平台相容性

01 的文字格式可以保持一致，但機器碼不一定可以跨平台使用。

例如：

ARM64 與 x86_64 使用不同的指令集。

Linux 與 Windows 具有不同的作業系統介面。

不同平台可能使用不同的呼叫慣例與記憶體配置機制。


因此，必須區分：

載入器可以在某個平台建置，不代表所有 .01 檔案都可以在該平台執行。

目前已驗證的 Hello World 範例以 ARM64 Linux／Android Termux 為主。其他平台仍需要分別建置與測試。


---

## 🔐 安全性

⚠️ 請勿執行來源不明的 .01 檔案。

01 執行的是原生機器碼，不是受到限制的腳本語言。

機器碼可能執行目前程序權限允許的操作，包括存取檔案或呼叫作業系統功能。

目前的子程序執行方式可以隔離部分程序層級的失敗，但不構成安全沙箱。它無法保證阻止機器碼存取系統資源，也無法保證惡意程式碼不會造成其他影響。

請只執行自己撰寫或已確認可信任的內容。

## 🤝 專案理念

很多程式語言希望讓人類更容易撰寫程式。

而 01 選擇從另一個方向出發。

不另外設計新的指令集，不建立新的機器碼模擬器，而是直接將二進位文字還原成位元組，並呼叫原生機器碼。

它不試圖取代所有程式語言，也不宣稱這種方式適合所有軟體開發。

它只是探索一個問題：

如果原始碼直接表達機器碼，開發流程可以變成什麼樣子？

這就是 01。
